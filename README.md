# KennyPvtHax

FastAPI backend + React (CRA/craco) frontend, deployed to Railway as a **single service**.
`build.sh` builds the SPA and copies it into `backend/static`, which FastAPI serves. The API
lives under `/api`, so the frontend and API share one origin and need no CORS in production.

The product catalog is currently **empty** by design — see `frontend/src/mock.js`.

## Layout

```
backend/server.py      FastAPI app, Mongo access, Telegram bot webhook
backend/static/        generated by build.sh (gitignored)
frontend/              React SPA
frontend/src/mock.js   site branding + catalog — populate this to add content
build.sh               Railway build: pip install, npm ci, npm build, copy static
railway.json           builder + start command + healthcheck
requirements.txt       runtime deps  (requirements-dev.txt adds test/lint tooling)
```

## Deploying to Railway

1. Create a project and add this GitHub repo as a service. `railway.json` is picked up
   automatically (NIXPACKS, `bash build.sh`, healthcheck on `/api/health`).
2. Add a MongoDB database — either the Railway Mongo plugin or MongoDB Atlas.
3. Set the service variables listed below. **Do not set `PORT`** — Railway injects it.
4. Generate a domain (Settings → Networking), then set `PUBLIC_BASE_URL` to that URL and
   redeploy so the Telegram webhook registers against the right host.

### Required variables

| Variable | Notes |
| --- | --- |
| `MONGO_URL` | Connection string. The app refuses to start without it. |
| `JWT_SECRET` | Long random string. The app refuses to start without it — a guessable value would let anyone mint an admin token. |

### Optional variables

| Variable | Default | Notes |
| --- | --- | --- |
| `DB_NAME` | `appdb` | Database name. |
| `PUBLIC_BASE_URL` | — | Your Railway/custom domain. Required for Telegram webhook registration. |
| `TELEGRAM_BOT_TOKEN` | — | Enables key delivery + owner commands. |
| `TELEGRAM_ADMIN_CHAT_ID` | — | Where order notifications go. |
| `ADMIN_EMAILS` / `ADMIN_TELEGRAMS` | empty | Comma-separated; grants admin in the UI. |
| `LOW_STOCK_THRESHOLD` | `3` | Low-stock alert threshold. |
| `CORS_ORIGINS` | `http://localhost:3000` | Local dev only; production is same-origin. |

See `backend/.env.example`.

## Custom domain

Railway → service → Settings → Networking → Custom Domain. Add the CNAME it shows to your
DNS provider, wait for it to verify, then update `PUBLIC_BASE_URL` to the new domain and
redeploy.

## Local development

```bash
pip install -r requirements-dev.txt
cd frontend && npm ci && cd ..

# terminal 1 — API on :8000
cd backend && MONGO_URL=mongodb://localhost:27017 JWT_SECRET=dev-only uvicorn server:app --reload

# terminal 2 — SPA on :3000, proxying to the API
cd frontend && npm start
```

Use **npm**, not yarn — `build.sh` and `package-lock.json` assume it.

## Production build locally

```bash
bash build.sh
cd backend && MONGO_URL=... JWT_SECRET=... uvicorn server:app --port 8000
```
